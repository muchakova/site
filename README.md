# muchakova.com

Личният сайт на Марина Мучакова, данъчен консултант. Двуезичен (BG/EN), статичен, изграден с [Eleventy](https://www.11ty.dev/) и публикуван в GitHub Pages.

## Бърз старт

Нужен е Node.js 20 или по-нов.

```bash
npm install          # веднъж
npm start            # локален сървър на http://localhost:8080 с презареждане при промяна
npm run build        # готов сайт в _site/
npm test             # build + всички проверки (вижте „Тестове“)
npm run test:lighthouse   # Lighthouse: скорост, достъпност, SEO (изисква Google Chrome)
```

## Как е подреден

| Път | Какво има |
|---|---|
| `src/bg/` | Българските страници. Публикуват се в **корена** на сайта, на старите адреси (`/`, `/services/`, `/blog.html` …). |
| `src/en/` | Английските страници. Публикуват се под **`/en/`** със същите пътища. |
| `src/_includes/layouts/base.njk` | Общата рамка: `<head>`, `hreflang`, хедър, футър. |
| `src/_includes/partials/` | Хедър и футър. |
| `src/_includes/layouts/` | `base.njk` (рамката), `post.njk` (статия), `doc.njk` (дълъг документ със съдържание: Поверителност, Достъпност). |
| `src/_includes/pages/` | Съдържание, общо за двата езика (напр. `home.njk`). Страниците в `bg/` и `en/` само го включват. |
| `src/_data/i18n/{bg,en}.json` | **Всички текстове на интерфейса**, включително етикетите за екранни четци. Двата файла трябва да имат еднакви ключове (тестът го проверява). |
| `src/_data/site.json` | Контакти, цени, социални мрежи, адреси на страниците. |
| `src/_data/services.json` | Четирите услуги на двата езика. |
| `src/_data/videos.json` | Видеата (заглавие, отговор, статия, дата и продължителност за Google). |
| `src/assets/` | Дизайн системата: `css/` (токени, база, компоненти), `js/site.js`, `icons.svg`, `favicon.svg`. Живият наръчник е на `/styleguide/`. Играта има свои `css/game.css` и `js/game.js` (текстовете в самата игра са в `game.js`). |
| `src/images/` | Оригиналните изображения. Публикуват се на `/images/…`, а в новите страници се превръщат автоматично в AVIF/WebP/JPEG в няколко размера. |
| `meet/`, `files/`, `robots.txt`, `llms.txt`, `CNAME` в корена | Публикуват се както са (`STATIC_FILES` в `eleventy.config.js`): пренасочването `/meet/` → `/booking/`, файловете за изтегляне, файловете за търсачки и домейна. Старият сайт е в историята на git (таг `pre-redesign-2026`). |

### Езиците

- Всяка страница, която съществува на двата езика, има в началото си еднакъв `key` (напр. `key: services`). Така се свързват `hreflang`, превключвателят на езика и `sitemap.xml`.
- Ако страница още няма EN версия, връзките от английския сайт водят към BG адреса. Филтърът `urlFor` решава това автоматично.
- Страница само на български (напр. наръчникът) се отбелязва с `i18nExempt: true`.

### Нова статия

1. Създайте `src/bg/blog/<адрес>.html` и `src/en/blog/<адрес>.html` (еднакво име на файла). В началото на всеки:
   ```
   ---
   title: "Заглавие"
   description: "Едно-две изречения за търсачките и картите в блога"
   date: "2026-11-02"
   tag: "ДДС"
   cats: ["taxes", "crypto"]
   ---
   <p>Текстът на статията…</p>
   <h2 id="bg-1">Първи раздел</h2>
   ```
   `cats` са темите за филтрите в блога: `taxes`, `crypto`, `invest`, `economy`, `business`, `institutions`. `tag` е етикетът, който се вижда (на езика на файла).
   По желание: `excerpt` (друг текст за картата), `seoTitle` (по-кратко заглавие за раздела на браузъра, ако заглавието е над 60 знака), `updated`, `ogImage`, `order` (подредба на статии от един и същи ден).
2. Пуснете `npm run og`: прави картинката за споделяне (по една за BG и EN). Ако статията има собствена корица, сложете `ogImage` и тази стъпка не е нужна.
3. Нищо друго не се редактира: началото, блогът, „Услуги“, свързаните статии, RSS, `sitemap.xml` и структурираните данни за Google се обновяват сами. Времето за четене се смята от текста.
4. Пуснете `npm test`.

### Нова страница

1. Създайте `src/bg/<път>/index.njk` и `src/en/<път>/index.njk` с еднакъв `key`, заглавие (`title`) и описание (`description`).
2. Текстовете на интерфейса добавете в двата файла в `src/_data/i18n/`.
3. Пуснете `npm test`.

## Тестове

`npm test` изгражда сайта и проверява:

| Проверка | Файл |
|---|---|
| Всички вътрешни връзки, изображения и `#котви` водят някъде | `tests/static/links.mjs` |
| Всеки адрес на стария сайт (`docs/redesign/legacy-urls.txt`) още работи | `tests/static/legacy-urls.mjs` |
| Еднакви ключове в `bg.json`/`en.json`; всяка страница има двойка с взаимен `hreflang`; няма български текст в EN страниците | `tests/static/i18n.mjs` |
| Валиден HTML | `html-validate` (правила в `.htmlvalidate.json`) |
| axe (WCAG 2.2 AA) в светла и тъмна тема, конзола без грешки, един `<main>` и `<h1>`, заглавия без прескачане, без хоризонтален скрол; на компютър и на телефон | `tests/e2e/pages.spec.js` |
| Смяна на език и тема, мобилно меню с клавиатура, видео, филтри, копиране, записване, играта, 404, RSS | `tests/e2e/interactions.spec.js` |
| Lighthouse: скорост ≥ 95, достъпност 100, добри практики ≥ 95, SEO 100, LCP < 2 s, CLS < 0,05 | `lighthouserc.json` |

## Публикуване

`.github/workflows/site.yml` изгражда и тества всяка промяна. Само клонът `main` се публикува в GitHub Pages.

> **Важно при пускането:** в GitHub → Settings → Pages → *Build and deployment* източникът трябва да се смени от „Deploy from a branch“ на **„GitHub Actions“** в същия момент, в който новият сайт влиза в `main`. Иначе GitHub ще публикува директно файловете от репото, а там изображенията вече са в `src/images/`.
